BLUEPRINT KELAYAKAN — MULTI-AGENT GOOGLE SHEETS DASHBOARD

Kesimpulan: FEASIBLE. Rekomendasi utama adalah React + TypeScript SPA dengan BFF/server-side sync read-only, cache terpusat, dan identitas Google terpisah per agent/domain data. Jangan panggil Google Sheets langsung dari browser dan jangan gunakan satu credential super-user lintas semua sandbox.

1) ARSITEKTUR REKOMENDASI
Browser → React SPA → BFF API → cache/database → worker konektor Finance/Sales/Product/PA → Google Sheets API. Komponen: (a) UI dashboard dan filter; (b) BFF untuk session, RBAC, agregasi, masking, dan kontrak API; (c) empat connector profile yang menyimpan credential dan allowlist spreadsheet/range masing-masing; (d) sync scheduler/queue dengan retry; (e) normalization layer yang mengubah tab/range berbeda ke canonical model; (f) cache Postgres untuk snapshot, sync status, provenance, dan audit; (g) secret manager + monitoring.

Boundary sandbox wajib dipertahankan end-to-end: satu principal/credential set per agent, satu connector config per agent, allowlist spreadsheetid + named range/tab, secret terpisah, cache row bertanda source_agent, dan authorization check di BFF. Tidak ada credential yang boleh bisa browse seluruh Drive organisasi. Spreadsheet dibagikan eksplisit sebagai Viewer ke principal connector terkait; connector Finance tidak menerima akses ke file Sales, dst.
